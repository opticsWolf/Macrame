# Macrame 0.20.0 — the valid axis for state

Crate macrame-db 0.19.3 at this commit, on `dev/0.20.0`, not merged and not released.
The version label is undecided: the plan says 0.20.0, the crate still says 0.19.3, and
the README revision row and the file-table range follow the label when it is set. Schema
**v22, unchanged**; payload and snapshot formats unchanged; `DbError` stays at **49**
variants; the Rust public surface is **1,957 items**, unchanged by P3 and P4. Decisions
**D-291** (P1), **D-292** (P2), **D-293** (P3) and **D-294** (P4).

`reconstruct(ts)` answers "what did we believe at `ts`". Nothing answered "what was true at
`v`" for the state as a whole, so the one read that folds the ledger knew a single clock.
This release gives the state fold the `AsOf` the traversal already takes, refuses the
concept overlaps that made the answer ambiguous, and measures the plans the new reads use.

## Breaking changes

None. Every surface change is additive. `reconstruct` is unchanged, and its SQL text is
byte-identical (plan gate 5).

## Added

- **`Database::reconstruct_as_of(AsOf)`** (D-292). `AsOf::valid_at(v)` answers what was true
  at `v`; `AsOf::bitemporal(v, r)` bounds that answer at a recorded instant. A valid read folds
  from genesis and ignores snapshots. An instant before anything valid is an ordinary empty
  state, and `predates_recorded_history` stays false.
- **`Database::verify_concept_intervals()`** (D-292, gate 10). Reports every pair of concept
  beliefs whose valid intervals overlap, naming both intervals.
- **Python:** `reconstruct_as_of(*, as_of_valid=None, as_of_recorded=None)` and
  `verify_concept_intervals()` on `Database`, and the `ConceptOverlap` class (D-294). The
  instants are keyword-only, so the two axes cannot be swapped by position.
- **Concept interval guard** (D-291). A concept has one belief per valid start, and at most one
  open interval. A write that overlaps a current belief is refused as `OverlappingConcept`, and
  two open intervals as `ConceptSingleOpen`. A batch is checked against itself before the
  transaction opens.
- **Refusals on the valid read** (D-292). Two beliefs that both claim the instant are refused by
  name, not answered: `ConceptSingleOpen`, `OverlappingConcept` or `OverlappingInterval`. The
  archive is consulted whenever one is present, because a superseded start can leave the hot log
  and still be the belief for its interval.

## Changed from the plan

- **The shipped valid predicate was superseded in P3 (D-293).** D-292 shipped
  `(?1 IS NULL OR recorded_at <= ?1)`. That form cannot seek `recorded_at`. P3 replaced it with
  two shapes: `VALID_FOLD`, with no bound, for the open read, and `VALID_FOLD_BOUNDED`, with
  `WHERE recorded_at <= ?1` in its text, for the bounded one.
- **P3's expectation was partly wrong, and the plan says so in place.** The plan expected the
  valid bound to reach the plan. It reaches it only in the bounded form, and only up to about
  half the log. The archive's cold side seeks only at the smallest bounds.
- **The candidate index was not built.** `(recorded_at, json_extract(payload, '$.valid_from'))`
  is now reached by the two folds that bound `recorded_at`, on its leading column. Its second
  column is still dead, and the plan keeps its temporary sort with the candidate, so it buys no
  ordering. D-196's arithmetic is re-run and recorded in D-293.
- **P4 is in.** It was marked optional, and it went in with the rest, as a keyword-only surface.

## What is not closed

- **Overlaps already in a ledger are reported, not repaired (§5.4).** A ledger written before the
  guard, or by raw SQL, keeps its overlaps. `verify_concept_intervals()` names them, and a read
  refuses only the instants that both beliefs claim. Raw SQL can still write an overlap.
- **The plan crossover is measured on one fixture, not stated as a rule.** The bounded valid fold
  seeks `recorded_at` up to about half of a 20,000-row log on a file-backed database, and scans from
  there. On the in-memory fixture the pins use, the recorded fold already scans at half the log, so
  the seek pins use a selective bound. The crossover depends on statistics, size and environment.
  Each pin names its bound for that reason.
- **Wall-clock cost of the bounded form at production size is not recorded.** An earlier probe
  compared the two forms on time, and its output was not kept, so this release cites no figures
  from it. The cold side's cost on a production-size archive is also unmeasured.
- **The candidate index is not built,** and nothing in this release needs it. It would need a
  workload that the crate does not yet have, and it would cost an index write per log row.
- **The version label, the crate version and the release row are open.** They are set when the
  label is chosen, not by this note.
- **The crash fault R15 is still open.** The default run completed cleanly on the final pass.
  Earlier default runs and the feature-off run crashed with `STATUS_ACCESS_VIOLATION` in some
  binaries. Those binaries passed when run alone, except `analyze_tests`, which crashed in two of
  six solo feature-off runs. So the fault is intermittent even alone, and it is R15 and not a
  defect this release introduced, though a clean baseline on `main` was not built to confirm it.
  Per D-147 a run that dies this way is re-run, and a binary that fails alone is a real failure.
- **The okfgraph re-import** of this release's thoughts is deferred, as the user asked.
