# Macrame 0.20.0 — the valid axis for state

Crate macrame-db 0.20.0, wheel 0.20.0, from `dev/0.20.0` merged to `main`. Schema
v22 → **v23**, index-only (D-300, D-301); concept log payload v3, unchanged; snapshot container v5 → **v6** (D-299);
MSRV 1.88, unchanged; `DbError` 47 → **49** variants; public surface 1,909 → **1,972 items**,
every one additive. Decisions **D-291** (P1), **D-292** (P2), **D-293** (P3), **D-294** (P4),
**D-295** (overlap provenance), **D-296** and **D-297** (CI and doc gates), and **D-298** and
**D-299** (two review rounds), and **D-300**…**D-302** (the two write-path regressions the release
bench found, fixed before the tag).

`reconstruct(ts)` answers "what did we believe at `ts`". Nothing answered "what was true at
`v`" for the state as a whole, so the one read that folds the ledger knew a single clock.
This release gives the state fold the `AsOf` the traversal already takes, refuses the
concept overlaps that made the answer ambiguous, and measures the plans the new reads use.

## Breaking changes

**One runtime change, no signature change.** The concept interval guard (D-291) refuses a
re-upsert at a new `valid_from` while the concept's earlier interval is still open. On 0.19.1,
`upsert_concept(ConceptUpsert::new("a", "Renamed").valid_from(TS2))` over an open `[TS, OPEN)`
succeeded; it now raises `ConceptSingleOpen` (`ConceptSingleOpenError` in Python). Close the
earlier interval first, or re-assert at the existing start. The repo's own fixtures changed for
exactly this (`tests/branch_write_tests.rs`, `tests_py/test_vector.py`).

Every surface change is additive. `reconstruct` is unchanged, and its SQL text is
byte-identical (plan gate 5).

## Added

- **`Database::reconstruct_as_of(AsOf)`** (D-292). `AsOf::valid_at(v)` answers what was true
  at `v`; `AsOf::bitemporal(v, r)` bounds that answer at a recorded instant. A valid read folds
  from genesis and ignores snapshots. An instant before anything valid is an ordinary empty
  state, and `predates_recorded_history` stays false.
- **`Database::verify_concept_intervals()`** (D-292, gate 10). Reports every pair of concept
  beliefs whose valid intervals overlap, naming both intervals.
- **Python:** `reconstruct_as_of(*, as_of_valid=None, as_of_recorded=None)` and
  `verify_concept_intervals()` on `Database`, and the `ConceptOverlap` class (D-294). The
  instants are keyword-only, so the two axes cannot be swapped by position.
- **Concept interval guard** (D-291). A concept has one belief per valid start, and at most one
  open interval. A write that overlaps a current belief is refused as `OverlappingConcept`, and
  two open intervals as `ConceptSingleOpen`. A batch is checked against itself before the
  transaction opens.
- **Refusals on the valid read** (D-292). Two beliefs that both claim the instant are refused by
  name, not answered: `ConceptSingleOpen`, `OverlappingConcept` or `OverlappingInterval`. The
  archive is consulted whenever one is present, because a superseded start can leave the hot log
  and still be the belief for its interval.

## Changed from the plan

- **The shipped valid predicate was superseded in P3 (D-293).** D-292 shipped
  `(?1 IS NULL OR recorded_at <= ?1)`. That form cannot seek `recorded_at`. P3 replaced it with
  two shapes: `VALID_FOLD`, with no bound, for the open read, and `VALID_FOLD_BOUNDED`, with
  `WHERE recorded_at <= ?1` in its text, for the bounded one.
- **P3's expectation was partly wrong, and the plan says so in place.** The plan expected the
  valid bound to reach the plan. It reaches it only in the bounded form, and only up to about
  half the log. The archive's cold side seeks only at the smallest bounds.
- **The candidate index was not built.** `(recorded_at, json_extract(payload, '$.valid_from'))`
  is now reached by the two folds that bound `recorded_at`, on its leading column. Its second
  column is still dead, and the plan keeps its temporary sort with the candidate, so it buys no
  ordering. D-196's arithmetic is re-run and recorded in D-293.
- **P4 is in.** It was marked optional, and it went in with the rest, as a keyword-only surface.

## Fixed after review (0.19.5, D-298)

- **Archiving no longer hides a concept start from the guard.** `LOG_ARCHIVABLE` archives a
  concept row only once a newer row exists for the same valid start, so each start's current
  belief stays in the hot log the guard reads. An archive written before 0.19.5 can still hold
  such a start; `verify_concept_intervals()` reports any overlap a write made against one.
- **`write_concepts` no longer splits a batch's verdict at a chunk boundary.** The ledger check
  reads each lineage's concepts in one query. (0.19.5 held a concept's rows in one chunk, which
  made every repeat a `RecordedAtRegression`; 0.19.6 replaces that, below.)
- **Valid-axis reads take a connection of their own once an archive exists**, so two concurrent
  `reconstruct_as_of(valid=…)` or `verify_concept_intervals()` calls cannot DETACH the archive
  under each other on `read_conn`.
- **`save_snapshot` refuses a valid-axis state** (`SnapshotWriteFailed`), which would otherwise
  become a recorded-axis anchor.
- A read that finds two open intervals says the second "is recorded", not "is refused".

## Fixed after review (0.19.6, D-299)

- **A concept's repeat starts a new chunk.** One chunk is one stamp, so two rows for one concept
  in it meet the monotonic `recorded_at` trigger. The batch is now its rows applied in order
  wherever the adaptive boundaries fall: a repeat commits, last row winning, and no chunk exceeds
  the adaptive size. The batch's check against itself runs before the first chunk, so a batch that
  contradicts itself is still refused with nothing written.
- **The valid fold decides once whether to attach the archive**, so a first archive created during
  a valid read cannot put the ATTACH on `read_conn`. With an archive, each valid read opens its own
  read-only connection, so a long `verify_concept_intervals()` does not hold the others back.
- **Concept rows without a `valid_from` archive again** (`IS`, not `=`, in `LOG_ARCHIVABLE`).
- **The valid-axis mark is serialised**, so a serde round trip cannot let `save_snapshot` accept a
  valid-axis state. The snapshot container goes to **v6**; v5 snapshots are skipped and folded
  from the log, as D-043 provides.

## Fixed before the tag (D-300, D-301, D-302)

The release bench read two write budgets far over their bounds. Both were regressions, and the
tag waited for them.

- **A concept upsert no longer costs its concept's history (D-300).** `write_path/upsert_concept`
  read 6.96 ms against ≤ 3 ms. The concept interval guard read every log row of the concept to
  find each valid start's belief, so one rewrite of a concept with 10,000 versions took 27.8 ms.
  The guard now seeks one row per distinct start on a new partial index,
  `idx_txlog_concept_starts`, which only concept rows pay for: 0.27 ms at 10,000 versions, flat.
- **The edge write path sheds its dearest index (D-301).** `chunk_budget/edges/90` read 6.31 ms
  against ≤ 3 ms, where 0.10.0 published 2.4. A bisect by release found no single defect: the
  indexes added since 0.12.6 each cost a little on every write and were never priced on it. A
  new probe priced each one, and `idx_txlog_entity` cost the most (1.10 ms of a 4.9 ms chunk)
  while serving one query, the archive's supersession test. That test now binds `table_name` and
  seeks the fold partition, and the index is dropped. Binding the table is also the correct rule:
  a newer row of a different table is a different entity and never made a row stale.
- **The budgets bench stops timing fixture teardown (D-302).** Every batched routine dropped its
  fixture, closing the database and deleting its directory, inside the timed region. Figures from
  0.20.0 on are the operation alone, so they do not compare directly with earlier releases'.
- **Schema v22 → v23**, one rung that creates the guard's index and drops `idx_txlog_entity`. It is
  index-only and runs at `open()`. A v23 file opened by a 0.19.x build is refused on schema version,
  as every newer stamp is.

## What is not closed

- **A backfill overwrites the live `concepts` projection.** The guard admits a non-overlapping
  past interval (§3.3), but `UPSERT_CONCEPT` still replaces the one projection row per id, and the
  log row is written by that row's trigger. After backfilling `[Jan, Jun)` titled "v1" under a
  current `[Jun, OPEN)` titled "v2", current-mode hydration, traversal and `as_of_valid(now)` show
  the concept as "v1" and no longer valid now. Only `reconstruct_as_of` answers correctly.
  Re-assert the current interval after a backfill. Fixing it moves the log write off the trigger,
  which is a schema change.
- **Overlaps already in a ledger are reported, not repaired (§5.4).** A ledger written before the
  guard, or by raw SQL, keeps its overlaps. `verify_concept_intervals()` names them, and a read
  refuses only the instants that both beliefs claim. Raw SQL can still write an overlap.
- **The plan crossover is measured on one fixture, not stated as a rule.** The bounded valid fold
  seeks `recorded_at` up to about half of a 20,000-row log on a file-backed database, and scans from
  there. On the in-memory fixture the pins use, the recorded fold already scans at half the log, so
  the seek pins use a selective bound. The crossover depends on statistics, size and environment.
  Each pin names its bound for that reason.
- **Wall-clock cost of the bounded form at production size is not recorded.** An earlier probe
  compared the two forms on time, and its output was not kept, so this release cites no figures
  from it. The cold side's cost on a production-size archive is also unmeasured.
- **`Overlap` keeps its `within_batch` bool, so the link arm of the valid fold still words a refused read as a refused write (D-295).** The concept payload gained a three-state `OverlapProvenance`; the edge payload shipped in 0.15.x and widening a public field there would break callers, so it is deferred to a breaking release.
- **The candidate index is not built,** and nothing in this release needs it. It would need a
  workload that the crate does not yet have, and it would cost an index write per log row.
- **The 90-edge chunk is still over 3 ms, at 3.99 ms on the corrected bench** (median of the
  three release sessions). What remains is
  indexes that each serve a registered reader, and none was traded for write speed without a
  decision. The adaptive chunk loop is what holds the bound (D-143): it stops on elapsed time and
  starts from 90, so the first chunk of an import runs over and later ones do not.
- **The crash fault R15 is still open.** The default run completed cleanly on the final pass.
  Earlier default runs and the feature-off run crashed with `STATUS_ACCESS_VIOLATION` in some
  binaries. Those binaries passed when run alone, except `analyze_tests`, which crashed in two of
  six solo feature-off runs. So the fault is intermittent even alone, and it is R15 and not a
  defect this release introduced, though a clean baseline on `main` was not built to confirm it.
  Per D-147 a run that dies this way is re-run, and a binary that fails alone is a real failure.
- **The okfgraph re-import** of this release's thoughts is deferred, as the user asked.
