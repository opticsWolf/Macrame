# Macrame 0.14.0 — what is guaranteed

Crate macrame-db 0.14.0, wheel 0.14.0. Schema v11 unchanged since 0.12.6; snapshot
container v3; MSRV 1.88 (the floor is libsql-ffi's, not ours). Public surface 1,313
items. Decisions D-170 … D-212.

Five waves (W7–W11) and an acceptance section read as evidence rather than ticked.
The public surface is a checked-in file at one canonical path per item, what 1.0
freezes is written down in one place (Appendix D), and the cycle was reviewed against
v0.13.0 item by item before the freeze: 601 → 619 items, 73 identities out and all 73
accounted for.

## Breaking changes

- **`as_of` split into two axes.** `as_of(ts)` compared one timestamp against both
  `links.valid_from`/`valid_to` (valid time) and `transaction_log.recorded_at`
  (transaction time). It is now `as_of_valid(v)` and `as_of_recorded(r)`; setting both
  is the BCDM cell the crate could not previously express. `as_of_recorded` reads a
  fold of the hot log bounded at `r` and refuses with `RecordedInstantUnreachable`
  when the horizon cannot be answered. Python gains `as_of_valid` / `as_of_recorded`
  on `traverse`, `traverse_ids` and `load_subgraph`, plus
  `RecordedInstantUnreachableError`. (W7.1, D-174, D-175; closes §3.1 and F-35)

- **Bulk paths report interruption with a distinct type.** `bulk_import`,
  `write_concepts`, `upsert_embeddings` and `write_analytics_annotations` return
  `Result<usize, BulkInterrupted>` where `BulkInterrupted` is `{ written, cause }`,
  so a caller can resume or report a committed prefix instead of a bare `DbError`.
  `From<BulkInterrupted> for DbError` keeps `?` working and puts the decision to drop
  the count at the call site. Python gains `progress=` and `cancel=` keyword-only on
  all four, with `CancelToken` and `BulkProgress` reporting written / total / rows /
  held after every commit. (W7.6)

- **The actor protocol left the public API.** `HighPriCommand`, `LowPriCommand` and
  `ChunkOutcome` are no longer public: they put seventeen tokio `oneshot::Sender`
  signatures into the 1.x surface for types nothing outside the crate can send. No
  test, bench or example anywhere constructs a command directly; the diff is
  60 removals and nothing else. (W11.2b, D-206)

- **`DbError` is now `#[non_exhaustive]`.** Matches against it need a wildcard arm;
  the guarantee that costs is bought back rather than written off. (W11.2c, D-207)

- **One canonical path per public item.** Twenty-three modules became `pub(crate)`;
  the prelude carries names, not namespaces. Public API moved +321/−640
  (1,632 → 1,313 items); 45 identities lost, 4 gained, all 49 accounted for, and no
  item left the API. Three modules stay public because each *is* the qualification:
  `connection::chunk_rows`, `schema::ddl`, `util::timestamp`. (W11.2d, D-208)

- **`Database` is `Send + Sync` and deliberately not `Clone`.** Cloning would
  duplicate the right to close — `cadence_stop`'s copy keeps the snapshot task writing
  against a database the caller believes is closed. Share with `Arc<Database>` and
  call `close()` on the last handle. (W11.1, D-203)

- **MSRV is 1.88.**

## Added

- **Snapshot container v3 with a CRC-32 header.** The loader knows the bytes are wrong
  before it deserializes any of them. v2 files are refused as
  `SnapshotIncompatible` and the scan folds from the log; nothing is in a snapshot
  that is not also in the ledger. (W8.2, D-185)

- **Fuzzing infrastructure**, feature-gated under `--features fuzzing`: libFuzzer
  harnesses for the snapshot reader, seed generation derived from the build under
  test, and — in the ordinary suite, on every platform — exhaustive bit-flip,
  truncation, mutation-behind-a-valid-checksum and 64 MiB decompression-bomb tests.
  (W8.4, D-187)

- **Half-life decay on search surfaces.** `search_vector` and `keyword_search` accept
  a half-life with an explicit instant, with the sign trap handled per surface
  (distance vs. bm25). Decaying surfaces read `rerank_depth(top_k)` first.
  `search_filtered` deliberately does not offer it. `HalfLifeWithoutInstant` refuses a
  decay without an instant. (W9.5, D-193)

- **Appendix D — the stability contract.** What 1.0 freezes is written in one place,
  normative alongside section 4 and Appendix A, with
  `tests/stability_contract_tests.rs` holding its quantities (1,313 items, schema v11,
  snapshot container v3, MSRV 1.88, eight doctrines) to this build. (W11.5, D-211)

- **A checked-in public API surface file** and the gates that come with it:
  public-api baseline, path canonicality, binding parity, doc currency and
  revision-history completeness. (W11.2a/W11.2d/W11.3/W11.4, D-205, D-208–D-210)

## Fixed

- **Retired concepts leaked through vector search.** `search_vector` never filtered
  `retired = 0`, so `hybrid_search` fused one ranked list honouring retirement with
  one that did not — the same ledger, two answers. One visibility predicate
  (`VISIBLE_CONCEPT`) is now spliced at all three readers (`search_vector`,
  `hybrid_search`'s vector arm, `FilteredVectorSearch::run_pre_filter`), and `top_k`
  escalates by doubling rather than quietly shrinking. (W9.3, D-191; closes F-31)

- **`load_subgraph_with` bound `now_ts` where the builder bound the traversal's own
  instant**, so a historical builder silently returned the present. `bind_params` is
  now the only producer of the parameter list. (F-35, D-175)

- **`hydrate_at_time` folded the hot log without asking whether the log could still
  answer.** After `archive`, a past instant inside an archived generation returned a
  silent empty `Vec`; it now returns `RecordedInstantUnreachable` naming the instant
  and `reconstruct` as the archive path. (W9.1, D-189)

- **A future-stamped row poisoned the floor it was read into.** `recorded_at_floor`
  took `MAX(recorded_at)` unbounded, so one row stamped in 2065 became the process's
  floor and manufactured more of itself. Open refuses with
  `DbError::FutureRecordedAt`, governed by `Tuning { future_stamps: … }`. (W7.4,
  D-178)

- **`reject_overlaps_within` held the writer 18.1 s on large batches.** Sorted sweep,
  `n log n` instead of quadratic, with the two adjacent-pair traps handled explicitly
  (equal `valid_from` re-assertion; open-interval eligibility). The batch that held
  18.1 s now holds 2.2 s. (W7.5, D-179)

- **Snapshot save and load blocked the async runtime.** bincode + zstd + fsync ran on
  tokio workers; both halves now run in `spawn_blocking`, with panics mapped to
  `ReplayCorrupt` on write and a fold-from-genesis on read. (W8.1, D-184)

- **`save_snapshot` was atomic about the file but not the name.** The directory is
  flushed after the rename, and a failed flush is reported rather than logged, because
  close() promises the final anchor. (W8.3, D-186)

- **`write_annotations_atomic` returned raw `DbError::Engine`.** It now classifies
  through `WriteOp::Annotation`; an annotation naming a missing concept returns
  `NotFound(concept_id)`. (W7.2, D-176)

- **`run_writer_actor` returned a `Result` that could not fail.** The actor returns
  `()` and join status is mapped by a named, tested `writer_exit`, pinned against a
  real `JoinError` from a panicking task. (W7.3, D-177)

- **`AttributeModeUnstated` still said `as_of`** after the axes were split; it now
  carries `StatedInstants` and renders the calls that produce it. Four stale
  intra-doc links fixed; the rustdoc gate is green again. (W7.7, D-183)

- **`OverlappingInterval` said "already holds" about a row that was never written**
  when raised by the batch-internal guard. (D-180)

## Performance

- **Graph algorithms run on a dense CSR view** built from `Subgraph`'s interned keys.
  At the 49,152-node / 544,767-edge budget ceiling with ULID-shaped ids: louvain
  675 ms → 75 ms, scc 310 → 34, dijkstra 125 → 28, k_core 24 → 24. End to end on the
  realistic fixture, ~81 ms → ~33 ms with the interior falling from 60% to 25%. No
  public signature moved. (W10.3, D-200, D-201)

- **`astar` came back off the dense view** — the one algorithm that returns early —
  and its regression gate now pairs each search with its own baseline and takes the
  minimum of the differences. (W10.3c, D-202, D-204)

## Measurements that closed questions

- **No second `PRAGMA optimize` call site.** Measured across 90 / 500 / 5,000 /
  40,000 edges on a fresh database: `sqlite_stat1` gains 7 rows and no plan and no
  opcode count moves. Not built, with the reasoning and the gate that proves it.
  (W10.2, D-198)

- **No bitemporal index.** The two axes never meet on a table; the transaction-time
  bound already seeks on `idx_txlog_time`, and a composite adds an index write per
  logged row forever with no read that gets faster. F-33 closed as "no index needed",
  pinned by `tests/bitemporal_plan_tests.rs` and the re-runnable
  `examples/bitemporal_index_probe.rs`. (W10.6, D-196)

- **Writer starvation is real on an ordinary closed-loop workload**, and the floor is
  refused on its price rather than its premise. (W10.4, D-199)

- **An opcode-count gate replaces an unavailable rows-scanned counter**: the gate is
  the program that would do the scanning. (W10.1, D-195)

## Documentation

- The 0.13.0 release note that was never written, including the two §8 corrections
  (analysis_limit does not bound ANALYZE's hold; `as_of` is not purely valid-time) and
  the two experiments that gave the wrong answer first.
- The two residues the 0.13.3–0.13.5 audit turned up: the foreign-key arm covers the
  annotation path only, and D-178 says what does *not* repair a poisoned file.
- The revision history is a gate: `tests/doc_currency_tests.rs` asserts the header
  version, the last row's span and the register anchor, so the drift D-144 named as a
  category cannot recur silently. (W11.4, D-209, D-210)

## Acceptance (§14, D-212)

The acceptance list was read as evidence, and four of its eleven items were not what
they said. `query_as_of_edges` was reviewed under item 1 and kept — the last public
name carrying the bare word `as_of`, bounded on one axis and reading current belief,
which is exactly `AsOf::valid_at`. §14.1 is the carry list "zero silent carries"
needed and did not have: C-1 the foreign-key arm on `links` and `concepts`, C-2
`save_snapshot` reporting I/O failure as `ReplayCorrupt`, C-3 `DbError::kind()`, C-4 a
build gate for `--no-default-features`, C-5 cargo-semver-checks at 1.0. The
top-level README's "scheduled for 0.14.0" claim about the Analyze/Optimize kind split
is corrected; it shipped in 0.13.24.
