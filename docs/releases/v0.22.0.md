Crate macrame-db 0.22.0, wheel 0.22.0, from `dev/0.22.0` → `dev/0.22.0-revA`.
Schema v24 → **v29** (edge kinds, the concept overlay, the overlay's row
laws, the version pool's search machinery, and the interval form of the
overlay's single-open law). Concept log payload remains **v3**;
snapshot container **stamps v28**. `DbError` 49 → **56** variants; public

the cycle's last full run). The cycle's shape: two tracks — the

decisions [D-307](../architecture/s13-decision-register.md#d-307) through
[**D-313**](../architecture/s13-decision-register.md#d-313)), then the

amendment: M6-P (the probes), M6-a through M6-e, decisions
[**D-314**](../architecture/s13-decision-register.md#d-314) (the overlay) and
[**D-315**](../architecture/s13-decision-register.md#d-315) (adoption), under
Amendment 2's §5.1–§5.5.

## The overlay (D-314)

A branch's correction of an inherited concept is a **version row on its own
lineage** beside the immutable mint, and a lineage may also **cut** a belief it
can see. The v26 rung added `concept_versions` (`WITHOUT ROWID`, PK
`(id, branch_id, valid_from)`) and `concept_cuts` (append-only), the versions
FTS both filled by triggers, and per-model `_version_embeddings` beside every
registered model. The write paths route per (lineage, id) at the act's stamp —
the mint, the inherited correction (W2, under
[D-312](../architecture/s13-decision-register.md#d-312)'s one-act-one-stamp
law), and adoption (W3, [D-315](architecture/s13-decision-register.md#d-315)) —
and the read paths resolve by the same walk the writes read: nearest version on
the path to the root, a covering cut answers absent and stops, one
open-or-absent per (id, branch) with no fall-through past the mint line. The
laws are differential-pinned by a real-reader oracle whose bookkeeping the pour
never reads back (`tests/m6_real_reader_oracle_tests.rs` with
`tests/common/m6_fixture.rs`), and by P-8's brute-force property suite
(`tests/m6_resolution_tests.rs`).

What callers notice first:

* a branch keyword/vector search **no longer returns a concept at the trunk's
  superseded text** — the union drops everything whose id resolves to a
  different version, the stale-hit red test the review priced high (K1). At
  production scale (1,000 versions over 100,000 concepts) the version-aware
  filter measured cheap; the per-lineage FTS rebuild fallback was declined on
  measurement (`docs/probes/m6-P3-search-scale.md`);
* an archive session keeps what a per-lineage pick reads — the overlay mirror
  rows never move, the fork-window guard is inclusive at a row's own stamp, the
  cold fold resolves through the archive's `branches` rows, `rehydrate` brings
  the mint back whole, `verify_concept_intervals` is per `(id, branch)`, and
  `archive_hint` answers per lineage;
* `concepts_by_id` below the hot fold's reach still refuses when the archive is
  missing (D-189's law, unchanged), now with overlay stores included.

## Adoption (D-315)

A lineage may write an ordinary first version of an id whose mint it cannot
see — off-path sibling, a past-cutoff mint, the trunk adopting a branch-born id —
nothing copied, nothing closed, superseded or cut, the provenance row still
naming the mint. A further write on an adopted id routes down the standard
overlay arms. A fresh adoption tagged `retired` is refused by name
(`DbError::AdoptedRetirement`, the 56th variant): the overlay's retirement is a
cut or a close, and both name a belief that was visible. With W1, W2 and
adoption every (lineage, id) concept write is routable, so the public API
cannot raise `CrossLineage` any more; the trigger keeps raising it for writes
that reach `concepts` directly. P-7's verdict (the review's gate): the edge
law lives in the FK alone, so adoption rides D-308's concepts-before-edges
batch order and the batch gained no new machinery.

## The conversation track (the plan §3-§4)

* **M1b (D-312)** — supersede in one write: close the open belief and open the
  next under one stamp, on the trunk and per lineage (the overlay's W2 rides
  the same machinery).
* **M2 (D-309's additions)** — pointers and functional edge kinds; the v25
  `edge_kinds` register; `check_functional` verified on every edge write path.
* **M3 (D-313)** — conditional pointer move (`expect=`): the claim and the move
  run in one transaction; the loser of a race writes nothing and reads back
  `PointerConflict { expected, current }` (the 55th variant). Python spells
  `db.set_pointer(..., expect=..)` with `macrame.UNSET` beside `macrame`.
  `Unset` for the three-state claim.
* **M4 (D-310's conversation pieces)** — pointer reads planned and pinned;
  the resolution's per-chunk fold reads by the D-303 rule, not by seq_id.

## Breaking changes

1. **A cross-lineage concept write that the old law refused as `CrossLineage`
   now succeeds or refuses differently.** A visible inherited id: a plain
   write over its open belief refuses as `ConceptSingleOpen` (never an
   implicit supersede) and a supersede succeeds as the W2 takeover — 0.14.8's
   `CrossLineage` was the guard's sentence, not the decision's. A lineage-off
   -path id: succeeds as adoption. Only the fresh-retirement shape gains a new
   class (`AdoptedRetirementError` in Python), because the act it asked for is
   not a thing the adoption can be.
2. **`DbError::CrossLineage` becomes trigger-only** (outside writers). Code
   that matched the variant from `upsert_concept` paths must move to the
   single-open/adoption classes; the Python class remains exported.
3. **The overlay's row laws reject what 0.21.0 stored without them**: a cut
   row refuses `UPDATE` (a cut is a decision, not a window), a version row's
   `recorded_at` is monotonic and its start `(id, branch_id, valid_from)` is
   immutable — schema v27, applied on the rung from v26.

## Costs on record

* The per-lineage keyword arm at scale: ~7 ms standing cost over the whole
  -file base on the light word; the widest word priced by the fetch loop's
  whole-corpus escalation, insensitive to version count — the one future row
  if very-wide-word branch search ever needs polish (`docs/probes/m6-P3
  -search-scale.md`).
* Storage: ~1.2-1.5 KB per version row (the mirror, the FTS row and the
  embeddings) — at the amendment's hoped share, ~1% of a 100k-concept store.
* The reader census (P-2): 27 `concepts` sites in 12 files — 15 content, 5
  identity, 7 write machinery, 2 guard/fixture — classified, with the K2 gate
  converting the next new reader on arrival.
