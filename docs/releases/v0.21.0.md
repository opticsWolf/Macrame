# Macrame 0.21.0 — one state rule for concepts

**DRAFT — from `dev/0.21.0`, not yet the tag.** Acceptance-gate figures finalize at
the release bench (gate 9).

Crate macrame-db 0.21.0, from `dev/0.21.0` (P1 shipped; P2–P4 ride the same branch
when their items land). Schema v23 → **v24**: `concept_disorder` added,
`idx_txlog_concept_starts` recreated with `valid_from DESC`, and every projection
0.20.0 left wrong re-derived from its rule row. Concept log payload remains **v3**,
byte-for-byte; snapshot container **stamps v24** — see the behaviour change below. The
release decision is [**D-303**](../architecture/s13-decision-register.md#d-303).

## Behaviour change

**`reconstruct` answers differently for a ledger that holds a backfill, and old
snapshots are skipped.** Through 0.20.0 a concept's recorded read picked its winning
row by write order (`seq_id`), so a backfill — a write whose `valid_from` starts
earlier than the belief the concept already held — overwrote the answer both in the
fold and, via the skip rule, in the projection. From 0.21.0 the state is decided by
one rule applied uniformly to every recorded read: **a concept's state is its open
belief, else its latest-starting belief**, over rows recorded at or before the read
instant. A later write cannot change what a past read returned (the rule obeys the
read's own bound, and the marks that drive the correction never clear); a
future-dated write is not open yet and is answered by its start once the bound
reaches it.

The v24 open repairs every ledger 0.20.0 wrote: projections whose `valid_from` is not
their greatest start are re-derived from that start's latest log row (the log row
count, the payload bytes and the trigger bodies are untouched), the disorder marks
are filled from written history — log **and** archive, so a pair whose backfill is
already partially archived is still marked — and healed or not, a pair whose history
ever held a backfill stays marked. Snapshot files stamped below v24 are refused at
the header, skipped with a warning, and the read folds from the log instead — which
returns the same answer the rule produces, at the cost of folding from genesis until
a new snapshot is saved.

Writers see the rule through one signal: the interval guard admits the backfill, the
projection is left alone, and the pair is marked — one extra insert per backfill
write, nothing on the normal path. The projection and the fold now hold the same
answer by mechanism rather than by workaround: the README workaround (re-assert the
current interval after a backfill) is obsolete and has been removed from the risk
table. Re-asserting the current interval is still allowed — it is the same-start
heal, recorded later, mark intact, past reads unchanged.

## Added

- **`concept_disorder`** (D-303, v24): the mark ledger the read pair probes (`EXISTS`,
  one scan) and the write path fills on the skipped-projection signal. Filled from
  history by the rung, never cleared by design: clearing would let a later write
  change what a past read returned.
- **Plan pins for the pair** (gate 4): the probe's one-scan program; the correction's
  per-file winner-seek plan with no whole-log arm, taken on a healed-and-`ANALYZE`d
  ledger as well as an unhealed one; VDBE triples alongside the plan text
  (`shape5_plan` in `src/temporal/replay.rs`).

## Changed

- `idx_txlog_concept_starts` stops `valid_from`-ascending: the correction's
  `ORDER BY valid_from DESC, seq_id DESC LIMIT 1` rides the v24 index with no
  right-part sort (VDBE 5-2-1 hot / 14-6-8 cold), and D-300's skip-scan still serves
  from the same index (pin re-run, gate 4).
- **Doctrine property** (gate 3): `doctrine_property_tests` now generates concept
  writes with out-of-order starts (backfill shapes marked, heals, guard refusals
  ignored) and asserts the fold and the projection agree field by field — the
  §2.2 coherence is generated-history-tested, not only fixture-tested.
