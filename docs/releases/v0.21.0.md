# Macrame 0.21.0 — one state rule for concepts

Crate macrame-db 0.21.0, wheel 0.21.0, from `dev/0.21.0`. Schema v23 → **v24**: `concept_disorder` added,
`idx_txlog_concept_starts` recreated with `valid_from DESC`, and every projection
0.20.0 left wrong re-derived from its rule row. Concept log payload remains **v3**,
byte-for-byte; snapshot container **stamps v24** — see the behaviour change below. MSRV 1.88, unchanged;
`DbError` stays at **49** variants; public surface 1,972 → **1,979 items**. Decisions
[**D-303**](../architecture/s13-decision-register.md#d-303) (the release decision),
[**D-304**](../architecture/s13-decision-register.md#d-304) (the 90-edge chunk's index set priced — drop nothing), and
[**D-305**](../architecture/s13-decision-register.md#d-305) (the widening completed, the break spent on the user's
say).

## Breaking changes

**`Overlap`'s `within_batch: bool` becomes `provenance: OverlapProvenance`** (D-305, P5 — spent
on the user's say: a pre-1.0 minor may break, and the same widening after 1.0 would cost a
deprecation cycle for identical wording). The edge error of 0.13.7 joins the state set the
concept errors have carried since 0.19.4 (D-295): `"already_recorded"` / `"same_batch"`
/ — the state the bool could not say — **`"both_recorded"`, a refusal the valid fold raised, where
the caller asserted neither interval and the ledger holds both.** The two write messages are
byte-identical to what 0.13.7 and 0.19.2 printed; the read arm stops wording a read as a write.
Python: the attribute `within_batch` on `OverlappingIntervalError` is renamed to `provenance`,
with the same string values the concept classes use. Public surface 1,972 → **1,979 items**.

## Behaviour change

**`reconstruct` answers differently for a ledger that holds a backfill, and old
snapshots are skipped.** Through 0.20.0 a concept's recorded read picked its winning
row by write order (`seq_id`), so a backfill — a write whose `valid_from` starts
earlier than the belief the concept already held — overwrote the answer both in the
fold and, via the skip rule, in the projection. From 0.21.0 the state is decided by
one rule applied uniformly to every recorded read: **a concept's state is its open
belief, else its latest-starting belief**, over rows recorded at or before the read
instant. A later write cannot change what a past read returned (the rule obeys the
read's own bound, and the marks that drive the correction never clear); a
future-dated write is not open yet and is answered by its start once the bound
reaches it.

The v24 open repairs every ledger 0.20.0 wrote: projections whose `valid_from` is not
their greatest start are re-derived from that start's latest log row (the log row
count, the payload bytes and the trigger bodies are untouched), the disorder marks
are filled from written history — log **and** archive, so a pair whose backfill is
already partially archived is still marked — and healed or not, a pair whose history
ever held a backfill stays marked. Snapshot files stamped below v24 are refused at
the header, skipped with a warning, and the read folds from the log instead — which
returns the same answer the rule produces, at the cost of folding from genesis until
a new snapshot is saved.

Writers see the rule through one signal: the interval guard admits the backfill, the
projection is left alone, and the pair is marked — one extra insert per backfill
write, nothing on the normal path. The projection and the fold now hold the same
answer by mechanism rather than by workaround: the README workaround (re-assert the
current interval after a backfill) is obsolete and has been removed from the risk
table. Re-asserting the current interval is still allowed — it is the same-start
heal, recorded later, mark intact, past reads unchanged.

## Added

- **`concept_disorder`** (D-303, v24): the mark ledger the read pair probes (`EXISTS`,
  one scan) and the write path fills on the skipped-projection signal. Filled from
  history by the rung, never cleared by design: clearing would let a later write
  change what a past read returned.
- **Plan pins for the pair** (gate 4): the probe's one-scan program; the correction's
  per-file winner-seek plan with no whole-log arm, taken on a healed-and-`ANALYZE`d
  ledger as well as an unhealed one; VDBE triples alongside the plan text
  (`shape5_plan` in `src/temporal/replay.rs`).

## Acceptance

Gates 1–11 ran as the plan's §6 spells them. Gate 8's eight mutants of
`connection.rs`, `replay.rs` and `migrations.rs` were each caught by their named
test and restored: `>=`→`>`, the skipped-write log insert, the correction's
`DESC`, the rung's trigger drop, mark left behind, correction-for-absent-pair,
heal-clears-mark, and the bounded correction unbound. The last two are caught
by the gate-11 stability case — a read at ts before and after a healing write
t2 — and marked the one fixture correction of the run: the fold-vs-s0 catcher
needs a non-empty sidecar (a mark for a different pair) while its watched pair
stays clean, because the probe is pair-blind and the statement's own join is
what filters the pairs.

## Changed

- `idx_txlog_concept_starts` stops `valid_from`-ascending: the correction's
  `ORDER BY valid_from DESC, seq_id DESC LIMIT 1` rides the v24 index with no
  right-part sort (VDBE 5-2-1 hot / 14-6-8 cold), and D-300's skip-scan still serves
  from the same index (pin re-run, gate 4).
- **Doctrine property** (gate 3): `doctrine_property_tests` now generates concept
  writes with out-of-order starts (backfill shapes marked, heals, guard refusals
  ignored) and asserts the fold and the projection agree field by field — the
  §2.2 coherence is generated-history-tested, not only fixture-tested.

## Measured this release

- **Gate 9, read and writer, vs `main-0.20.0` recorded on the tag (criterion, machine at
  2–4%).** Write side: `upsert_concept` **−4.5%**, `concepts/70` chunk **+5.1%**. Read
  side: the replay stations' baseline recorded on the `v0.20.0` code, re-measured here on
  a clean target (the figure of record) — `reconstruct_full_fold` **+1.14%** (16.667 vs
  16.589 ms; a first pass read +0.20%, p = 0.52, none detected), `reconstruct_composed`
  **+2.16%** (3.046 vs 2.980 ms; the probe-and-correction pair's probe plus statement
  prep, tens of µs on the small-delta arm).
  The disorder probe's stations re-measured on the final code: healthy folds
  indistinguishable (−0.6% … +0.6%), the probe alone 0.5 µs per 1,000 calls; at 5%
  incidence the healed steady state reads **+9.5%** (marks persist, pre/post-heal reads
  Δ0) against the probe-preview's ≈ +8%; at 100% incidence **+37.7%** against the
  preview's +44% (a station the plan itself calls noisy). All inside the ±10% gate where
  the gate applies.
- **P2 (D-304, the 90-edge chunk's index set): priced, nothing worth dropping.** The three
  `transaction_log` indexes are load-bearing on the write itself (dropping one costs up to
  2.5 ms); the cheapest real candidate saves 0.84 ms against a reader whose cheaper alternative
  was once 68 s.
- **P3 (R15 five-by-five): 0.20.0 crashes 3× as often as 0.19.1** (3/5 vs 1/5 crash-runs,
  clean release builds, every crashed binary clean standalone). Road to 1.0 W1 owns the fix.
- **P4:** the bounded valid fold reads ≈ 12.5 ms hot on the release bench's graph fixture,
  and the archive-attached arm reads ≈ 2 ms — the archive file is less history, not overhead.
  `extra`'s 64 KiB cap sits ≈ 117× over the largest real frontmatter the okfgraph bundle
  carries (14 documents, 7…562 bytes).
