# Macrame 0.15.0 — what is guaranteed

Crate macrame-db 0.15.0, wheel 0.15.0. Schema v11 → **v15**; snapshot container header
still v3, payload format v3 → **v4**; MSRV 1.88 unchanged. Public surface 1,313 → **1,624
items**. `DbError` 33 → **41 variants**. Decisions **D-213 … D-242**.

One wave (W12) and twenty-five releases, all of it branching: a lineage of belief that
forks, reads its ancestry as of the fork point, writes its own rows beside its parent's,
answers what it concluded, and is abandoned in one transaction. A fork writes **one row**
and copies nothing.

The shape of the cycle is that the plan was wrong in public more often than it was right,
and every refutation is a measurement rather than a rewrite. §15.3's "traversal gains a
factor of chain depth" is a constant. §15.4's "`links` is not keyed by lineage, and that is
unreachable through the crate" was reachable for seven releases. §15.4's "divergence is
exactly the set of rows carrying the branch's own id" is wrong in both directions. §15.4's
"an abandoned branch's rows are a contiguous archivable set by construction" is false
twice. Three acceptance criteria in §17 are restated rather than ticked, each because the
criterion as written pins an answer the work refutes.

## Breaking changes

- **`MaterializedState::edges` is `Vec<EdgeBelief>`, not `Vec<(String × 5)>`.** The four
  replay folds partitioned per lineage from schema v12 and none of them *projected*
  `branch_id`, so the label was lost on the way out of SQL and `fold_delta` keyed its map
  on the edge key — one slot, two beliefs, survivor decided by emission order. The struct
  is `#[non_exhaustive]` **with a constructor**: `save_snapshot` is public and takes a
  `MaterializedState`, so the attribute alone would have made a public function uncallable
  from outside the crate. (W12.5, D-222)

- **`SNAP_FORMAT_VERSION` 3 → 4 — a payload change under an unchanged v3 header.** `bincode`
  is not self-describing, so a v3 payload read as a v4 shape does not fail: it reads the
  *next* edge's `source_id` as this edge's `branch_id` and runs off the buffer later as
  `ReplayCorrupt`. A fault to chase, and an upgrade is not one. Old snapshots are refused;
  nothing is lost, because a snapshot is a cache. (W12.5, D-043)

- **Schema v15 widens `links`' primary key** to `(source_id, target_id, edge_type,
  valid_from, recorded_at, branch_id)`, and `cold.links` takes the same key in the same
  release. `branch_id` goes **last**, on plans rather than on §15.3's reasoning: appending
  keeps the five-column covering seek the archive sweep runs per candidate row; leading
  with it drops that to one bound column. A primary-key diff is forbidden after 1.0
  (D-036) and this is what D-032 reserves the pre-1.0 window for. Additive in what it
  *admits*. (W12.15, D-232)

- **A branched read that names an unregistered lineage raises `UnknownBranch`, not
  `NotFound`.** `NotFound` reads "node {0} not found" — the wrong noun for a branch.
  A break for anyone matching that variant. (W12.7, D-224)

- **`EdgeAssertion` and `ConceptUpsert` are `#[non_exhaustive]`.** (W12.8, D-225)

- **Python: `reconstruct`'s edges cross as a six-tuple**, with `branch` after
  `valid_to`. `query_as_of_edges` stays at five — a read that named its lineage does not
  need the label repeated back, and a fold of the whole ledger is answering a question a
  forked ledger answers twice. §14's "more than five fields should be a class" does not
  reach it, because `branch` is a `str` after a `datetime | None` and a misindex fails on
  type. A **seventh** field is the recorded trigger to make it a class. (W12.5)

## Added

- **`macrame::branch`** — the eleventh public module. `BranchId` (validated, refused rather
  than trimmed: a trailing space is not a typo, it is a second lineage that prints as the
  first), `Branch`, `BranchView`, `Divergence`, `MAX_BRANCH_ID`.

- **`Database::fork(name, from)` and `Database::branches()`.** A fork reads no ledger table
  and copies nothing: a thousand forks against a seeded ledger leave `links`,
  `links_current`, `concepts` and `transaction_log` byte-identical, asserted as a count in
  both languages. `fork` returns a `Branch` where §15.4 wrote `-> BranchId`, because the
  name is the one value the caller already has and the **fork point** is what they cannot
  derive without a second query. (W12.7, D-224)

- **The read resolves lineage in two shapes.** `LineageShape::Trunk` emits the pre-0.14.4
  SQL byte for byte; `Resolved` emits the ancestry join. One row in `branches` is a
  *sufficient* condition rather than a heuristic — `branch_id` is `NOT NULL DEFAULT 'main'
  REFERENCES branches(branch_id)`, so a one-row register is a database in which every
  ledger row reads `'main'` because nothing else could be stored. Nearest-ancestor wins,
  not `branch_id IN (ancestry)`: the union form returns the branch's corrected row *and*
  the ancestor's superseded one, which makes a shadow retirement a no-op — measured, trunk
  1,111 nodes, union 1,111, nearest 1,000. (W12.4, D-220)

- **The fork point is a visibility cutoff, and the read is a hybrid rather than a filter.**
  `links_current` answers *current as of now* and structurally cannot answer *current as of
  t*: `trg_links_current_sync` carries `recorded_at` forward on every correction, so once
  an ancestor churns an edge the version the branch is entitled to see is not in the
  projection at all — and `recorded_at <= cutoff` over it *removes* the edge and everything
  reachable only through it. So `links_cut` unions the projection for keys the ancestors
  have not touched with a per-lineage log fold for the keys they have, disjoint by
  construction. Cutoffs narrow at every hop under a running minimum and never widen, which
  is why the fold needs no cross-ancestor tiebreak anywhere. Edges are cut at fork points
  and **concepts are not**: belief forks, vocabulary does not. (W12.6, D-223)

- **The write path carries lineage.** `EdgeAssertion::on_branch`, `ConceptUpsert::on_branch`,
  `Database::retire_edge_on`, and `branch_id` bound by `INSERT_LINK` and `UPSERT_CONCEPT`.
  Retirement across lineages is **shadow retirement** — the branch writes its own closed row
  at the ancestor's key and the read prefers it by distance. The alternative, closing the
  ancestor's row, is the parent corruption Doctrine III forbids, which answers a question
  `trg_links_single_open` had parked in the schema since v12. (W12.8, D-225)

- **`BranchView`** — a `Database` plus a `BranchId`, so a caller who forked reads and writes
  through the fork instead of naming it at every call. It buys **no capability**, and that
  is what makes it one release rather than a fifth of them. The `Arc` is the design:
  `Database::close` takes `self` by value and an `Arc` cannot surrender that while a clone
  survives, so a view cannot end the handle it reads through — D-203's argument for
  declining `Database: Clone` reaching the use §15.4 reserved it for. (W12.9, D-226)

- **`Database::diff(a, b)` and `BranchView::diff(other)`**, returning `Divergence`. One
  statement over two resolutions, not two reads and a Rust subtraction: two statements
  against `read_conn()` are two snapshots, so a write landing between them yields a
  reported difference that existed at no instant. No `ts` parameter, and that is a decision —
  a shadow retirement *is* a divergence about an instant having passed, so any valid-time
  filter drops the branch's side and answers "no difference". (W12.11, D-228)

- **`Database::archive_branch(name)`** — one lineage's whole ledger to the cold file: its
  `links`, its `concepts`, its `transaction_log` entries **and** its `branches` row, in one
  transaction. The chain has no branch points: if the links go the log must go, or
  `reconstruct(now)` folds the log, yields the branch's open edges, and disagrees with
  `links_current`; and `hot_log_reach`'s soundness rests on "the newest row per entity is
  never archivable", which is false of a predicate taking a whole lineage — so the
  `branches` row must go too, and *that* is what converts a silently short fold into a
  correct one. Afterwards the name is unknown and a read naming it is refused, rather than
  being handed its parent's view with nothing in the answer to say everything the branch
  believed had been deleted. **That refusal is the release's real content.** (W12.13, D-230)

- **Seven `DbError` variants** (33 → 40): `InvalidBranchId`, `UnknownBranch`, `BranchExists`,
  `ForkPrecedesParent`, `CrossLineage`, `BranchMismatch`, `BranchNotArchivable`.
  `CrossLineage` closes a guard that had been in the schema since v12 with no arm in
  `classify` — machinery written for an unbuilt caller is exercised by nothing.

- **Three `CommandKind`s**: `Fork`, `ArchiveBranch`, `ShadowSwap`. Each appended at the end
  of the declaration order, because `self as usize` indexes per-kind arrays and the order
  binds the Python surface — placing `Fork` beside the other write commands compiled,
  passed, and would have shifted six labels.

- **Schema v12–v15.** v12: the `branches` register, `branch_id` on all four ledger tables
  with a real foreign key, `links_current` re-keyed per lineage, three log triggers
  redefined, four guards, and the four replay folds partitioning per lineage. v13: one
  trigger body — `trg_branches_frozen_delete` becomes conditional on an archive session, and
  `cold.branches` arrives. v14: `idx_lc_lineage_cut`. v15: the `links` key above.

- **Python reaches all of it in the same release** — W6's convention held six times and
  lapsed once, recorded. `branch=` on `traverse`, `traverse_ids`, `load_subgraph`,
  `search_filtered` and `query_as_of_edges`; `Database.fork`, `.branches`, `.diff`,
  `.archive_branch`; `Branch`, `Divergence`, `EdgeBelief`; a `BranchView` **written in
  Python**, because the structural half of the Rust guarantee does not cross and a pyo3
  class would have implied a guarantee it could not keep; and eight exception classes —
  `BranchError` as a seventh intermediate group over `UnknownBranchError`,
  `BranchExistsError`, `BranchNotArchivableError`, `ForkPrecedesParentError`,
  `CrossLineageError`, `BranchMismatchError`, plus `InvalidBranchIdError` under
  `ValidationError`. `BranchId` deliberately has no Python class: the Rust type earns its
  keep by making the validated form unforgeable, and Python has no equivalent to enforce.

## Fixed

- **The archive predicates crossed lineages, and both spellings deleted rows the ledger
  still believed.** A link's `entity_id` carries no lineage, so `LINKS_ARCHIVABLE` asked for
  "a later assertion for the same interval key" without asking whose: the trunk asserts
  `a → b`, a branch forks and asserts at the same key, one `archive` runs, and **the trunk
  stops reaching `b`**. It runs in both directions — an abandoned branch could delete the
  trunk's history simply by having been written to last. Separately, "a closed interval is
  history" is false of a shadow: archiving a branch's retirement row lets the ancestor's
  open row win the resolution again, so an operation that mints no assertions **un-retires
  an edge**. Nothing caught either, because `audit_current` asks whether `links_current` is
  the image of `links` and the archive re-derives the projection from what survived — the
  drift audit can see a projection that disagrees with the ledger and cannot see a ledger
  missing rows. (W12.12, D-229)

- **`query_as_of_edges_on` never got the fork-point cutoff.** D-223 reached the two readers
  built by the shared builder and not the third, which spells its own SQL — so for four
  releases a branch that forked in February was handed the trunk's March edge, and when the
  trunk retired an inherited edge the reader returned the graph with that edge simply gone
  while the traversal on the same lineage reached it. Two public readers, one lineage, a
  disagreement neither answer mentioned. **The pattern, named because it is not about this
  function:** a surface that does not go through the shared builder misses every repair made
  to the shared builder, and it misses them quietly, because the repair's tests are written
  against the builder. (W12.10, D-227)

- **`reject_overlapping_interval` read `links_current` with no lineage predicate at all.**
  Exact while every row was `main`'s and wrong in both directions at once thereafter: a
  branch refused for overlapping the belief it forked in order to supersede, the trunk
  refused for overlapping a branch's belief it cannot see. `AND branch_id = ?` is **not**
  the repair — it fixes the trunk and inverts the branch, which is defect AA reintroduced
  across lineages by the fix for it. What ships is the read's own resolution narrowed to one
  edge key: *what a lineage may not overlap is what that lineage can see*. (W12.8, D-225)

- **Four migration rungs described today's schema rather than their own.** They restored
  indices by looping over the live `CREATE_INDICES`, which broke the moment v14 declared an
  index over `links_current.branch_id`: v2→v3, v3→v4, v5→v6 and v10→v11 all failed with
  `no such column: branch_id` on databases that legitimately had no such column. Ten
  migration tests, one cause, latent since v3. Each rung now names what it owes through
  `create_indices`, which panics on a name no declaration matches. Three rungs had the same
  shape with triggers, found one wave earlier. (W12.14 / W12.2, D-231, D-217)

- **A ladder guard that was checking the baseline.** `the_ladder_reaches_the_current_version`
  walked from v0, where the baseline step `from: 0, to: SCHEMA_VERSION` is found first, lands
  on the top, and reports success on **any** steps array — including one with every
  incremental rung deleted. Found by mutation. It now starts at v2, and a second test names
  which rung is missing. (W12.14, D-231)

- **One `CommandKind` covered two structural hold distributions.** `ShadowRebuild` carried
  both the fill chunks, meant to fit `CHUNK_BUDGET`, and the swap turn, which builds three
  indexes under the write lock at 46.8 ms against 3 ms and cannot — so **every successful
  rebuild put a permanent entry in `budget_violations()`**, the method documented as the
  one-line answer to whether the bound is holding. A counter that cannot be zero trains
  discounting. `ShadowSwap` is now its own kind and exempt; the fill half stays counted.
  (W12.16, D-233)

- **C-1 closed one release early**: a refused edge returns `NotFound` naming the endpoint
  that is absent, rather than a `FOREIGN KEY constraint failed` that had gone from ambiguous
  between two columns to ambiguous between three. The release that made the message worse is
  the one that answers for it. (W12.2, D-218)

## Performance

- **The branch chain is a constant, not a factor of chain depth.** 1.1–1.3× the unfiltered
  traversal at chain depths of 1, 10 *and* 100, on the same connection, whether the branch
  holds nothing or the rows are dealt across the whole path: the ancestry CTE is materialised
  once per query, so it is an addend on the query rather than a multiplier on the hops.
  "Traversal gains a factor of chain depth" was §15.3's main argument for keeping option (2)
  within reach. (W12.3, D-219)

- **The cutoff read costs 1.45× / 1.81× / 2.65× at 0% / 9% / 90% churn**, against a
  prediction written down first so the result could disagree with it — and half of it did.
  Churn-linearity held; the **1.45× at zero churn** did not, and zero churn is what a fresh
  fork looks like. The fixed cost is in the fold arm's machinery rather than its rows.
  (W12.6, D-223)

- **`idx_lc_lineage_cut` (v14): branched 6.50 → 5.43 ms, churned 16.94 → 7.45 ms**, trunk
  unmoved at 1.64. The rung §15.4 owed — "`idx_lc_traversal_cover` gains `branch_id`" —
  does **not** reproduce and is not what ships: D-219 measured it against a query shape that
  stopped existing two releases before the rung came due, and every `branch_id`-leading shape
  takes the trunk walk off its covering index, which is a guarantee dropped rather than a
  slower plan. Cost stated rather than buried: 2,000 assertions 18.3 → 20.6 ms, +12.6%, paid
  by every database while only forked ones collect. (W12.14, D-231)

- **The v15 rebuild is linear and cheap**: 3.6 ms at 1,000 rows, 15.3 at 10,000, 105.8 at
  50,000 — cheap because no trigger fires, the insert targeting `links_v15` while every
  trigger on the table names `links`. Recorded against the v6 → v7 rung, whose cost is on
  record as an unmeasured 2× estimate. (W12.15, D-232)

## Measurements that closed questions

- **A branch inherits concepts rather than restating them.** `concepts.id` keeps its
  `NOT NULL UNIQUE` and its parenthood of `links`; `branch_id` there is provenance and never
  identity. Measured on libSQL: widening the uniqueness leaves every insert failing with
  `foreign key mismatch`, and a composite key forbids the copy-on-write that makes a fork
  O(1). What it costs is stated rather than minimised — a branch cannot correct or retire a
  concept it did not mint — with the overlay that would buy it, its five costs, and the
  retirement symptom that reopens the question. (W12.2, D-214)

- **The invariant the schema promised is uncheckable.** `ddl` had said since v12 that `fork()`
  would enforce `forked_at >= parent.created_at`. The trunk's `created_at` is stamped from
  the wall clock during migration, before the injected clock is resolved and unable to move
  after it — so the comparison is between two clocks and refuses every fork on every fixture
  in the crate. What ships is `forked_at >= parent.forked_at`: same clock by construction,
  guaranteeing fork points are non-decreasing down a root path, which is exactly what
  D-223's ancestry clamp already assumed. Found by building what the comment described.
  (W12.7, D-224)

- **`links` was keyed lineage-blind and it was not unreachable.** §15.4 argued from the clock:
  successive calls return strictly increasing values, so two writes cannot share a stamp.
  True of two *sequential* writes and describing nothing the crate does in a batch —
  `write_bulk_atomic` and `bulk_import` take **one stamp for the whole batch** by contract,
  because the rows were asserted by one act. Reachable since 0.14.8, and pinned as a
  guarantee by a test that asserted the `UNIQUE` failure and explained why it could not
  happen. **A gap pinned as a guarantee is a gap nothing will ever report.** (W12.15, D-232)

- **A branch is transaction time with a tree order, not a third axis** — and the confirmation
  is that the doctrine count did not move. A ninth doctrine for branching was the easy edit
  and the wrong one: lineage is a property of the transaction-time axis, so it is a clause in
  Doctrine II. The gate that would have caught a ninth doctrine is the gate that confirms
  this was a clause. (W12.1, D-213)

## Documentation and gates

- **Three gates were not gates, and none of the three is a defect in the library.** `ci.yml`
  triggers on `push: [main]` and `pull_request`, and `dev/0.15.0` was neither with no pull
  request — so **no CI run existed for any of W12's sixteen releases**; every one was gated
  locally and read, so the claim that fails is not *unverified* but **unreplicated**, on one
  Windows box, and the first run on Linux and macOS found something at once. The fuzz gate
  bounded whole-process RSS with `-rss_limit_mb` when its assertion is about a single
  allocation, failed on AddressSanitizer's 202 MiB free-quarantine over 570,597 executions on
  an **empty** input, and thereby skipped v0.14.0's crates.io publish. And
  `scripts/check_public_api.py` documented three exit codes and had only ever had two,
  because `sys.exit("…")` with a *string* prints and exits 1. (W12.17, D-234, D-235, D-205)

- **And a fourth, which was a decision rather than an oversight.** The quarantined property
  step was wired as a release gate while `Cargo.toml` had said since 0.8.0 that the set is
  "unusable as a gate on Windows" — the sentence that is the quarantine. At 65% red on a
  healthy tree it had no contrast between healthy and unhealthy output, so blocking on it
  selected the runs where the coin landed heads; v0.14.0's publish took two reruns against a
  tree nothing was wrong with. It now runs, reports and blocks nothing, with a four-state
  verdict on the run's summary page, and [D-234](../architecture/s13-decision-register.md#d-234)'s
  release obligation gains the clause that replaces the block. **The rule the four share:**
  an instrument with no contrast between its healthy and unhealthy output is decoration —
  whether it always passes, always fails, cannot be zero, or never runs. (W12.19, D-236)

- **The exhaustive match moved inside the crate.** `#[non_exhaustive]` on
  `DbError` bought minor-version error variants and charged callers the one
  guarantee that told them they had considered everything. `DbError::kind()` is
  one match with **no wildcard arm**, in the crate that defines the enum — so a
  variant added without a classification does not compile. The twelve
  `ErrorKind` values are not a new taxonomy: they are the seven groups the
  Python bindings already publish plus the five failures that belong to no
  group, and a new gate holds the two spellings together across all forty-one
  variants. `ErrorKind` is itself `#[non_exhaustive]`, because an exhaustive one
  would make a new *category* of failure a major version — D-207's own rejected
  trap, one level up. +57 items. Closes **§14.1 C-3**, and with it the table.
  (W12.25, D-242)

- **A configuration that was compiled for two waves and never run.** CI's only
  `--no-default-features` gate was `cargo check --all-targets`, which proves the
  configuration compiles. Nothing proved its 613 tests pass — while the README
  published that count and D-154 stated in writing that the path "is still built
  and tested". The suite now runs with metrics off on ubuntu. C-4 asked for a
  build gate *instead of* the check and the measurement refused the phrasing:
  the check is the only gate that builds the `harness = false` bench, and the
  run is the only one that can fail an invariant `src/metrics.rs` deliberately
  keeps un-gated so it runs in the non-recording build. Both are kept, each
  proved by mutation to see what the other cannot. Closes **§14.1 C-4**.
  (W12.24, D-241)

- **A full disk said the ledger was damaged.** Every failure inside `save_snapshot` returned
  `ReplayCorrupt` — *"replay corrupt at seq N"*, the worst thing this system can say about
  itself — when nothing in that function can touch the log. The same correction was made to
  the *read* path at 0.13.12 and the write path kept the wrong subject for ten releases.
  `DbError::SnapshotWriteFailed` is the forty-first variant and the only member of its family
  where nothing is damaged and nothing is lost: a snapshot is a cache, so the previous anchor
  still stands and the cost is a slower start. Closes **§14.1 C-2**. (W12.23, D-240)

- **A test that was calibrated for one machine, found by the machine that was faster.**
  `a_swap_over_budget_is_not_a_violation` asserts its fixture made the swap exceed the chunk
  budget before it claims anything about the exemption; on `windows-latest` the swap took
  **2.572 ms against a 3 ms budget**, on a commit green everywhere else. The swap has no
  smaller unit — 25.4 ms at 3,200 × 4 here — so the fixture grew, with the margin measured
  rather than assumed. **Contrast can be a property of the machine rather than of the
  instrument.** (W12.22, D-239)

- **§17 item 4, the last criterion owed a build, and what it was reaching for.** The
  cross-branch edge the criterion refuses cannot be represented; the *reach* it was
  reaching for can, and is accepted at assertion and refused at abandonment with the
  concept named. The abandonment guard says *any other lineage* and had only ever been
  tested through the trunk — the one lineage that can never be abandoned. Four tests, three
  mutations, and the remedy the error message instructs is now walked end to end.
  (W12.21, D-238)

- **`mypy --strict` had been failing since 0.14.9, and that gate was never broken.** `BranchView`,
  the one hand-written Python file in the package, shipped with no annotations on twelve methods —
  19 errors, against a README that advertises `mypy --strict` in CI as a guarantee. It went
  unseen for the same reason [D-234](../architecture/s13-decision-register.md#d-234) names:
  `python.yml` triggers on pushes to `main` and on pull requests, and `BranchView` has never
  existed on `main`. All twelve signatures are now annotated. **This is the first defect D-234's
  standing obligation actually turned up**, and unlike the four instrument findings it is a defect
  in the crate rather than in the plumbing. (W12.20, D-237)

- **The public-API script now holds appendix D to the baseline it blesses.** A `cargo test`
  gate already checked that number, but blessing happens after the suite has run: at 0.14.15
  the baseline went to 1,556 while the appendix said 1,555, and the gate was **red at HEAD
  through a shipped release** because the only thing that could see it had already passed.
  (W12.17)

- **The exemption criterion is re-anchored on inapplicability**, with both falsified
  predecessors kept, because the house records evolutions rather than final states. v1
  (*expected-on-healthy is exempt*) is refuted by `Optimize`, which runs on every close and
  stays counted; v2 (*if `over_budget` can differ from `turns`, count it*) is refuted by
  `Archive`, `Rehydrate` and `Checkpoint`, all of which can come in under budget. Both are
  observational; **inapplicability is decidable at design time**, which is what lets a
  criterion settle the next case instead of rationalising the last. (W12.17, D-233 amended)

- **Four stale claims found by reading, in four consecutive releases**, each a comment
  predicting a release: `on_branch` said `fork()` arrives at 0.14.5 (it arrived at 0.14.7);
  the road map's binding-convention bullet said "held four times" over a list of five; §5.7
  said the v7 → v8 rung is the only one that suspends foreign keys (v11 → v12 has since it
  shipped); and the plan's own §15.4 predicted no public-API movement for v12, which moved
  by +18.

### The README told new users to depend on 0.13

`README.md`'s Rust quick start pinned `macrame-db = "0.13"` when this release was tagged,
two minors behind the crate it introduces. It is not an internal document: crates.io and
PyPI both render it as the package's front page, so that line is the first instruction a
new user follows, and a stale pin sends them to a series this repository has stopped
changing.

It survived this release's version sweep because the sweep searched for `0.13.0` and
`0.14.0` — full versions — and a two-component pin is neither. It was found by a reader.

The fix is two characters; the gate is the point. `tests/doc_currency_tests.rs` exists
because [D-144](../architecture/s13-decision-register.md#d-144) named documentation drift
a *category* rather than an incident, and this is that category one document further out:
a mechanical claim, in a file nobody rereads while writing code, wrong in a way no reader
of the code can see. A fourth assertion holds the pin to `Cargo.toml`'s `major.minor`, and
the shape test gains a line so that a quick start which moves — taking the parser's anchor
with it — fails loudly rather than passing on nothing. No register entry: this is
[D-209](../architecture/s13-decision-register.md#d-209)'s gate reaching one file further,
not a new decision.

## Acceptance (§17, D-212)

Nine criteria, of which **three are restated rather than ticked** — each because the
criterion as written pins an answer the work refutes, and each restatement is a register
entry rather than an edit:

| # | State |
|---|---|

**Item 4 was the one item still owed a build, and 0.14.21 built it** (D-238). The

caller cannot span two lineages with an edge, but can make one lineage's belief depend on
another's *vocabulary*, and the ledger's answer to that is in two halves. Accepted at
assertion, because the predicate that refused it would also refuse the trunk naming a
branch's concept — the inheritance an O(1) fork is built on. Refused at abandonment, where
the reach becomes a contradiction: `alpha` cannot be forgotten while `beta`'s hot edge names

witness a general predicate could have. `tests/cross_branch_tests.rs` pins both halves and
walks the remedy the error text instructs, including the step where retirement alone is not
enough. The three refusals a caller can otherwise reach — `BranchMismatch`, `UnknownBranch`,
